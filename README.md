# mooze-client

Mooze is a mobile wallet for Bitcoin and Liquid Network assets, with integrated PIX (the Brazilian instant payment system).
The app logic lives in a Rust core. A Flutter app calls the core through flutter_rust_bridge.

![Mooze Logo](apps/mobile/assets/logos/logo_primary.svg)

## Desktop testnet MVP

A React + Tauri desktop client is available in `apps/frontend` and `apps/desktop`.
Run `npm ci` and `npm run desktop:dev` from the repository root.
See [desktop setup, architecture, and verification](docs/desktop-mvp.md).

## Features

- **Bitcoin and Liquid**: on-chain Bitcoin and Liquid wallets in one app.
- **PIX**: buy Liquid assets with Brazilian Real (BRL) through PIX deposits.
- **Swaps and pegs**: swap Liquid assets and move between Bitcoin and Liquid through SideSwap.
- **Store mode**: a merchant interface to receive payments.
- **Custom node**: connect to your own Electrum server.

## Supported assets

- Bitcoin (BTC)
- Liquid Bitcoin (L-BTC)
- DePix (DEPIX) on Liquid
- Tether USD (USDT) on Liquid

## Repository layout

| Path | Contents |
|---|---|
| `apps/mobile` | Flutter app (UI, state management, platform integration). |
| `crates/mooze-core` | Rust core with the application logic. Builds for native targets and for `wasm32-unknown-unknown`. |
| `crates/mooze-app` | Host-neutral application facade over `mooze-core`. Every client (flutter_rust_bridge today, Tauri and wasm next) binds it. |
| `packages/mooze_core_bridge` | Flutter plugin that connects the app to the core through flutter_rust_bridge. |
| `docs/superpowers` | Design spec and implementation plans. |

## Architecture

```
apps/mobile (Flutter UI)
      │  Dart bindings generated by flutter_rust_bridge 2.11.1
packages/mooze_core_bridge (plugin + native ports)
      │  Rust API
crates/mooze-core (application logic)
```

- **`mooze-core`** holds the wallets (BDK for Bitcoin, LWK for Liquid), PIX, SideSwap swaps and pegs, login and session, prices, payment URIs, storage and sync.
  The core does no I/O itself. It calls platform traits ("ports") for HTTP, WebSocket, storage, secure storage, the clock and blocking work.
- **`mooze_core_bridge`** implements the ports for mobile:
  - A file-per-key store for app data.
  - Secure storage through `flutter_secure_storage` (iOS Keychain, Android Keystore).
  - A tokio runtime for network calls, and a WebSocket client for SideSwap.
- **Chain access**: the mobile app uses Electrum, with the same default servers as before and an optional custom node.
  The core also supports esplora over HTTP, which a browser build needs.
- **Data**: on first launch after the update, the app copies its local data (drift database, transaction database, preferences) into the core once.
  Secrets stay in secure storage under the same keys.

Read the design spec in `docs/superpowers/specs/2026-10-05-mooze-core-design.md` and the plan in `docs/superpowers/plans/2026-10-05-flutter-bridge.md`.

## Getting started

### Prerequisites

- [fvm](https://fvm.app) with Flutter 3.41.9. The version is pinned in `.fvmrc`.
- Rust (stable) through [rustup](https://rustup.rs).
- For iOS: Xcode and CocoaPods. Add the Rust targets:
  ```bash
  rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
  ```
- For Android: Android Studio, the Android SDK and NDK 27.0.12077973. Add the Rust targets:
  ```bash
  rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
  ```
- Java 17 to 23 for Gradle. Gradle 8.10.2 does not run on the Java 25 that recent Android Studio versions bundle.
  Point Flutter to a supported JDK:
  ```bash
  fvm flutter config --jdk-dir <path to a Java 17-23 home>
  ```

The first build compiles the Rust core from source. Expect several minutes and a few GB of build output.

### Set up and run the app

1. Clone the repository and go to the app:

   ```bash
   git clone https://github.com/mooze-labs/mooze-client.git
   cd mooze-client/apps/mobile
   ```

   Run all Flutter commands below from `apps/mobile`.

2. Install dependencies:

   ```bash
   fvm flutter pub get
   ```

3. Run code generation:

   ```bash
   fvm dart run build_runner build --delete-conflicting-outputs
   ```

4. Run the app. Pass the SideSwap API key for swaps and pegs:

   ```bash
   fvm flutter run --dart-define=SIDESWAP_API_KEY=<key>
   ```

   To use another backend, add `--dart-define=BACKEND_API_URL=<url>`.

### Build for production

```bash
fvm flutter build apk --release --dart-define=SIDESWAP_API_KEY=<key>
fvm flutter build ios --release --dart-define=SIDESWAP_API_KEY=<key>
```

Debug Android builds also compile the core for the x86 emulators, so they take longer than release builds.

## Working on the Rust core

```bash
cd crates/mooze-core
cargo test
cargo clippy --all-features --all-targets -- -D warnings
```

- The `electrum` feature adds the Electrum backend. It is native-only.
- To build for the browser, build without `electrum`. Do not use `--all-features` for wasm:
  ```bash
  cargo build --target wasm32-unknown-unknown --features http-reqwest
  ```
  On macOS, the system `ar` writes empty archives for wasm objects. Use the LLVM tools from Homebrew:
  ```bash
  AR_wasm32_unknown_unknown=/opt/homebrew/opt/llvm/bin/llvm-ar \
  CC_wasm32_unknown_unknown=/opt/homebrew/opt/llvm/bin/clang \
  cargo build --target wasm32-unknown-unknown --features http-reqwest
  ```
- Pin every dependency to an exact version (`=x.y.z`). Check new dependencies with `cargo deny check advisories bans sources`.

## Working on the bridge

The Rust API that Dart sees is in `packages/mooze_core_bridge/rust/src/api/`.
After you change it, regenerate the Dart bindings with flutter_rust_bridge_codegen 2.11.1:

```bash
cargo install flutter_rust_bridge_codegen --version 2.11.1 --locked
cd packages/mooze_core_bridge
flutter_rust_bridge_codegen generate
```

The codegen version must equal the `flutter_rust_bridge` version in the plugin's `pubspec.yaml` and `rust/Cargo.toml`.

Run the bridge tests. The Dart smoke test calls the real native library on your machine:

```bash
cd packages/mooze_core_bridge/rust && cargo test && cargo build
cd .. && fvm flutter test test/bridge_smoke_test.dart
```

## Tests

- Flutter unit and widget tests: `fvm flutter test` in `apps/mobile`.
- On-device core test: it connects a test wallet over Electrum and syncs it through the core. It needs network access.
  ```bash
  fvm flutter test integration_test/core_bridge_test.dart -d <device id>
  ```
- CI (`.github/workflows`):
  - The Flutter app builds on every pull request to `main`.
  - The core builds and tests for the host and for wasm32 when `crates/` or `packages/mooze_core_bridge` changes.
  - The bridge crate is tested, the Dart smoke test runs, and `cargo deny` checks dependencies.

## Security notes

- Never share your mnemonic phrase or PIN with anyone.
- The mnemonic stays in the platform secure storage (iOS Keychain, Android Keystore). The core reads it from there to sign.
- Transactions are signed locally on your device. Private keys never leave your phone.
- Report vulnerabilities as described in [SECURITY.md](SECURITY.md).
